## 1 设计背景与目标

本系统面向校园 WiFi 故障调查场景：用户在楼门外已连接 WiFi，却无法访问网页，回到楼内后恢复。项目介绍与设计文档已将核心能力确定为“像工程师一样调查”，即依据观测提出假设、检查证据、寻找反证，并在信息不足时保留判断。

本阶段将上述流程转化为可操作的网页。用户可以选择案例，查看问题和观测，回放调查样例，阅读支持证据、其他解释和建议，并导出记录。当前提交侧重前端布局、交互及状态表达；独立预览使用模拟网络数据和预存规则执行结果，不代表网页正在进行现场探测或实时大模型调用。

## 2 参考材料与风格决策

老师提供的 `5-antho-front-design.md` 强调先确定明确的审美方向，再统一字体、色彩、空间与交互。本设计选择克制的主机主页风格，避免把工具做成密集的统计仪表盘。

用户明确指定参考 NS 主机的主界面，要求“简约，但是不至于单调”。我们提取其横向内容选择、大面积留白、清楚的焦点轮廓与底部快捷操作的组织方法。页面不使用 Nintendo 标志、游戏封面、截图或专有素材；案例图案由本项目使用内联 SVG 绘制。

参考包 `13-ai_copilot_html_example_pack_backend` 的 frontend 包含 HTML、CSS、JavaScript 三层结构，演示点击、加载提示、错误处理、结果面板与后端请求。本项目沿用这种清楚的文件分工和交互思路，重新设计页面结构、文案、案例卡片和证据展示，没有沿用实验室介绍、联系人等示例内容。

曾考虑三种呈现方向：传统后台仪表盘便于密集展示，但不符合本项目规模和用户偏好；杂志式介绍页适合说明理念，但难以承载调查操作；主机主页式案例选择兼顾识别度与实际操作，因此采用第三种，并在下半部保留清楚的调查工作区。

## 3 页面信息架构

页面由五部分组成：

| 区域 | 内容 | 设计目的 |
| --- | --- | --- |
| 顶部状态 | 项目标识、当前预览或运行状态 | 用户一进入就知道当前环境 |
| 项目引导 | 标题“门外的信号，还连着吗？”及一句说明 | 交代真实使用场景 |
| 横向案例架 | 10 张案例卡片、当前案例编号和问题 | 像选择一个调查任务一样进入系统 |
| 调查工作区 | 问题、运行方式、观测、证据与结果 | 支持完整的调查阅读过程 |
| 底部导航 | 调查、记录、观测及快捷键提示 | 提供稳定且容易找到的操作入口 |

桌面端工作区采用左右两列：左侧为入口和设置，右侧为证据工作区。移动端改成上下排列，保留横向案例选择。长 JSON 默认折叠，避免用户先读大量字段才能找到结论。

## 4 视觉规范

| 项目 | 设计值或规则 |
| --- | --- |
| 页面背景 | 米灰色 `#F1F0EB`，减少纯白页面的空泛感 |
| 正文主色 | 深灰绿 `#353B3A` |
| 焦点色 | 青绿色 `#39B6A9`，用于选中与键盘焦点 |
| 工作区底色 | 浅色 `#FAFAF6`，配细边框 |
| 卡片配色 | 低饱和绿、沙色、蓝灰等，与独立线条图案组合 |
| 字体 | 英文与数字优先 Bahnschrift，中文使用 Microsoft YaHei UI，均有本地回退字体 |
| 数据字体 | Consolas 或等宽字体，帮助阅读参数与返回值 |
| 卡片尺寸 | 桌面约 208 × 208 px；窄屏约 170 × 170 px |
| 动效 | 约 0.18 秒轻微位移，支持减少动态效果偏好 |

案例卡片使用统一比例，通过编号、图案与短标题区分内容。选中状态由描边和可读标题共同说明，不只依赖颜色。圆角和阴影保持克制，不加入无关装饰图片、游戏动画或大面积渐变。

卡片短标题用于课堂展示中的内容导航，不作为模型实验输入。真正的模型对照应使用中性的原始观测与固定协议，避免把场景名称当成答案线索。

## 5 主要交互

### 5.1 案例选择

用户点击卡片后，选中框、案例编号、问题文本和原始观测同步更新。桌面可使用左右方向键，触屏可横向滑动。每张卡片提供包含案例编号及问题的可访问名称。

### 5.2 独立预览与样例回放

直接打开 `index.html` 时，页面读取 `data.js` 中的本地数据，不需要安装依赖。点击“回放样例”后，展示此前保存的规则执行记录，并明确提示“非本次 AI 调用”。样例问题保持只读，避免把编辑后的新问题与旧记录混为一谈。

独立模式中在线模型和真实模型记录选项不可用，页面说明需要后端接入。不会因没有服务而虚构模型回答，也不会用动画假装工具正在执行。

### 5.3 证据与结论阅读

结果区优先显示当前判断，再展示候选假设、支持证据、反证、限制和下一步建议。证据以文字描述呈现，并附来源编号。工具输入及原始返回可按需展开，方便教师检查实现细节。

“地址异常候选”“无线链路待核查”“证据不足”等文字用于表达判断强度。界面不把所有问题都显示为已解决，也不将不确定状态作为页面错误。

### 5.4 记录、观测及导出

“记录”入口列出本地预存样例，可重新载入；“观测”入口展开原始数据。导出功能生成 JSON，并在独立模式附加 `sample_replay` 标记和来源说明。没有结果时，导出按钮禁用。

### 5.5 后端接入状态

前端预留读取案例、发起调查、读取历史记录和评测汇总的接口。接入服务后可以根据实际返回展示加载、成功和失败状态。在线失败明确显示错误，不静默替换成规则样例。本次前端验收不等于后端、模型对照或最终课程报告已经完成。

## 6 文件组织与数据边界

```text
frontend/
├── index.html    页面结构和语义元素
├── style.css     布局、配色、焦点和响应式规则
├── app.js        案例选择、状态、展示和导出
└── data.js       模拟观测与预存规则 Trace
```

页面不使用外部 CDN、图片或字体请求，便于课堂离线展示。不提供 API Key 输入框，不在浏览器本地存储中保存密钥。动态观测及模型返回先进行字符转义，结果文本不会直接作为可执行 HTML 插入。

本地样例用于检验页面交互与信息表达，其诊断准确性和专业规则仍属于后续系统评测范围。后端接入使用的字段与预存结果不同，需分别保留来源及执行状态。

## 7 响应式与可用性

850 px 以下工作区改为单列，手机端保留横向案例架，设置项在更窄宽度下纵向排列。正文、按钮、结果和 JSON 容器均限制在页面宽度内。底部导航固定，页面预留底部空间，使末尾内容可以滚动至导航上方。

按钮、选择框和文本框具有焦点提示；输入框有明确标签；状态区域使用实时状态语义。减少动态效果时关闭平滑过渡。当前未进行专业屏幕阅读器或完整 WCAG 审核，不据此宣称全面无障碍达标。
